# EPIC-07 AIリスト生成 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 条件から最大80項目の構造化リストを生成し、編集・除外して通常リストへ保存できる。Free は生涯1回、Premium は日本時間の月20回で、失敗・安全拒否・キャンセルで回数が戻り、同じ `requestId` で二重消費されない。

**Architecture:** 共有スキーマを型の源にし、サーバーは `aiRequests` / `aiUsage` の状態機械(transaction)と、差し替え可能な `AiClient`(偽実装を Emulator・CI で使う)で `generateList` を実装する。保存は既存のリスト作成部分を共通化して再利用する。モバイルは Callable クライアント・`aiRequests` の購読・純粋関数・画面に分ける。

**Tech Stack:** zod(`@soroe/shared`)、Cloud Functions v2 + Admin SDK、Vitest、Jest + @testing-library/react-native、Firebase Emulator、Node `.mjs`。

**Spec:** `docs/superpowers/specs/2026-10-20-epic-07-ai-design.md`(機能仕様書 8章・AC-05)。

## Global Constraints

- 上限・定数: AI 最大項目数 **80**、タイムアウト **30秒**(再試行は1回)、同時生成 **1件**(予約は **120秒** で失効)、レート制限 **1分5回**、
  Free は **生涯1回**、Premium は日本時間(UTC+9)の暦月 **20回**、リスト上限は既存どおり Free 3件。
- 入力: 自由記述・メモは最大500文字、人数は 0〜20(合計1以上)、泊数 0〜14、年齢帯は子どもがいるときだけ。
- モデル名の既定値: Free `gpt-5.6-luna`、Premium `gpt-5.6-terra`(`config/ai` の `freeModel` / `premiumModel` で上書き。仮の値)。
- 実際の OpenAI クライアントは作らない。`AI_CLIENT=fake` で偽実装、未設定は「AI生成は準備中です」。
- 想定内の不成立は `status` つきの応答で返し、`HttpsError` は認証・不正入力・権限だけに使う。
- ネイティブ依存を追加しない。UIに絵文字・Unicode記号をアイコンとして使わない。
- native と web の Repository は同じシグネチャ(`typeof Native.xxx`)。
- CLAUDE.md: 作業後は PR を作り、CI 通過後に `code-review` でセルフレビューする。

## Review Focus

1. 同じ `requestId` の再送・同時実行で、回数が二重に引かれず、結果も二重に作られない → Task 3 の統合テスト。
2. 失敗・安全拒否・キャンセルで回数が戻り、成功後に結果を捨てても戻らない → Task 3 / 4。
3. 予約中に2件目は `busy`。120秒を過ぎた予約は失効し、回数を戻してから新しい予約を受ける → Task 3。
4. Premium の月の境界: UTC 2026-10-31T15:00:00Z は日本時間 11/1 で、別の月の回数として数える → Task 2 / 3。
5. AI の結果が空・81件以上・重複・形式不正のとき、整形または失敗として扱い、不正なまま保存できない → Task 2 / 4。
6. 保存: 編集後の項目が80件超・不正は拒否、保存直前のリスト上限、再送は同じ `listId`(リストが2つできない)→ Task 4。
7. 他のユーザーの `aiRequests` は読めない → Task 4 の Rules テスト。
