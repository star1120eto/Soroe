## 1. 設計判断

### 1.1 招待トークン(クライアント生成・サーバーはハッシュのみ保存)

- クライアントが256bit乱数(`expo-crypto` の `getRandomBytes(32)`、hex 64文字)を生成し、
  `createInvite` に渡す。サーバーは SHA-256 を計算して `invites/{tokenHash}` として保存し、
  **平文トークンは保存しない**(仕様「推測困難な乱数、保存時はハッシュ化」)。
- このトークン自体が `createInvite` の冪等性キーを兼ねる(同一トークンの再送は新規作成せず、
  最初の結果を返す)。サーバー生成+requestId方式だと、レスポンス喪失後の再送で平文トークンを
  再提示できず、平文を保存するか別のリンクを再発行するしかなくなるため、この形を採る。
  トークンの強度はオーナー自身にしか影響しない(他人のリストへの権限は生まれない)。
  衝突(別リスト/別ユーザーが既に使用中)は `token-conflict` として拒否する。
- 招待URLは `https://soroe.app/invite/<token>`(ドメインは Issue #8 で確定までプレースホルダ。
  `soroe://invite/<token>` でも同じルートに入る)。

### 1.2 データモデル

```text
invites/{tokenHash}
  listId: string
  inviterId: string
  status: 'active' | 'revoked'
  createdAt: Timestamp
  expiresAt: Timestamp   // createdAt + 7日
  revokedAt: Timestamp | null

lists/{listId}/members/{uid}   // 既存。displayName を非正規化して追加
  role: 'owner' | 'editor'
  joinedAt: Timestamp
  displayName: string          // 参加時点の表示名。既存データは欠落しうる(UIでフォールバック)

users/{uid}/acceptInviteRequests/{requestId}   // acceptInviteの冪等性(成功時のみ作成)
  listId, createdAt
```

- 1リストにつき有効な招待リンクは常に高々1本。`createInvite` が同リストの `active` 招待を
  同一transaction内で `revoked` にする(仕様「再発行時は古いリンクを無効にする」)。
- 期限切れは `expiresAt` で判定し、`status` は書き換えない(クリーンアップは本EPICの対象外)。
- Rules: `invites` は **オーナーのみ読取可**(`isOwner(resource.data.listId)`、`listId == X` で
  絞ったクエリに限る)、書込みは全拒否。平文トークンは保存していないためオーナーが読んでも
  リンクは復元できない(UIは「招待中・有効期限」の表示と、再発行・取消だけを提供する)。
  非オーナー/未認証のプレビューは `getInvitePreview` Callable(Admin SDK)経由に限る。
- `members` への `displayName` 追加に伴い、`createList`/`duplicateList` は呼び出し元の
  `users/{uid}.displayName` をオーナーのmemberドキュメントへ書く。

### 1.3 Callable Functions

| 関数 | 認証 | 概要 |
|---|---|---|
| `createInvite({listId, token})` | 必須 | オーナーのみ。アーカイブ/削除済みリストは不可。`{inviteId, expiresAt}` |
| `revokeInvite({inviteId})` | 必須 | 現オーナーのみ。取消済みは冪等に成功 |
| `getInvitePreview({token})` | **任意** | リスト名・招待者名・メンバー数のみ返す(項目は返さない)。無効理由は `status` で返す |
| `acceptInvite({token, requestId})` | 必須 | 期限・取消・削除・自分招待・既参加・Free上限を検証し editor で参加 |
| `removeMember({listId, memberUid})` | 必須 | オーナーのみ。自分自身は不可 |
| `leaveList({listId})` | 必須 | editorのみ。ownerは `owner-cannot-leave` |
| `transferOwnership({listId, newOwnerUid})` | 必須 | 現オーナーのみ。対象は現在のeditor1名。原子的に入れ替え |

- 「想定内の不成立」(期限切れ、上限など)は例外ではなく判別可能なユニオン(`status`)のレスポンスで返し、
  UIが理由ごとに出し分けられるようにする。認証なし・不正入力・権限なしは `HttpsError`。
- `acceptInvite` の上限判定は `addMemberTransaction` と同じく参加確定と**同じtransaction内**で行う。
- メンバー追加/削除/移譲は、`members`・`users/{uid}/listRefs`・全メンバーの `memberCount`/`role` を
  1つのtransactionで更新する(`listRefs` はclient書込み不可なので不整合の窓を作らない)。
- 権限喪失は `members/{uid}` の削除で即時に効く(Rulesの `isMember` が `exists` で判定するため)。
  購読中の端末は `permission-denied` を受け取るので、UIが「アクセスできなくなりました」を表示する。
