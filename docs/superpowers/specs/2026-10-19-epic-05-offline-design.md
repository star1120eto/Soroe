# EPIC-05 オフライン・同期・競合 設計

対象: `docs/soroe-implementation-backlog.md` の OFF-001〜003。
受け入れ条件の正は `docs/soroe-functional-specification.md` の 12章(OFFLINE-01 / SYNC-01)、
AC-03、ITEM-01(項目編集の競合)。

## 1. 目的と背景

キャッシュ済みのリストを機内モードで開き、追加・編集・完了・削除が即時に反映され、復帰後に自動で
同期されて別端末へ届く。同時に編集しても、他のメンバーの変更を黙って壊さない。

Firestore のネイティブ永続化により、オフラインの読み書きと復帰後の再送は既に動く(SPIKE-001で合格)。
本EPICは、その上に「いまオフラインか・何が未同期か」を利用者へ見せること、オンライン必須の操作を
理由つきで止めること、競合を仕様どおり扱うこと、それを自動テストで保証することを足す。

## 2. 現状(実装済み)

- 項目の追加・編集・完了・削除は、キャッシュへ即時に反映される(Rules付きのclient write)。
- 項目一覧の購読は `includeMetadataChanges` で `hasPendingWrites` / `fromCache` を受け取る。
- リスト詳細に「未同期の変更があります」の帯がある(1秒以上続いたときだけ表示)。
- 項目編集は、保存時に `updatedAt` を編集開始時と比べ、変わっていれば2択ダイアログを出す。ただし
  保存は**全項目**を書く(他のメンバーが別の項目を変えても上書きする)。
- 削除は論理削除(`deletedAt`)。他端末で削除された項目の編集画面は「見つかりません」になる。

## 3. ゴール・非ゴール・アンチゴール

**ゴール**

- オフラインの表示(上部の帯)と、開いているリストの未同期件数、手動の再試行。
- オンライン必須の操作は、オフライン時に押せず、理由を表示する。
- 項目の編集を、実際に変えた項目だけの保存にし、別の項目の変更は自動統合する。
- 同じ項目の変更がぶつかったときだけ、「あなた/相手」を並べた比較を出す。
- 編集中に項目が削除されたら削除を優先し、入力内容を新しい項目として追加できる。
- AC-03(機内モード・2端末・削除対編集・復帰後同期)をEmulator上の自動テストにする。

**非ゴール**

- NetInfo 等のネイティブ依存の追加(開発ビルドの作り直しを避ける)。
- 一覧画面での未同期件数の表示(一覧の参照は Cloud Functions が書くため、端末の未送信を持たない)。
- 実機・2台のシミュレーターでの手動確認(ENV-002。Emulatorの自動テストで代替する)。
- 複数リストをまたぐ未同期件数、バックグラウンド同期、同期失敗のサーバー側リトライ。

**アンチゴール(技術的に動いても失敗とみなす)**

- 起動直後やアプリ復帰時に、誤って「オフライン」と出てちらつく。
- 他のメンバーが別の項目を変えたのに、保存で上書きして失わせる。
- オフライン中に押せるように見えて、押すと黙って失敗する操作が残る。

## 4. 設計

### 4.1 接続状態(OFF-001)

- `ConnectivityProvider` を認証済みグループ(app)に置き、`users/{uid}` を `includeMetadataChanges`
  つきで1本だけ購読する。`snapshot.metadata.fromCache` が true の間をオフライン候補とする。
- 候補が3秒続いたときだけ `isOffline = true` にする(起動直後・復帰直後の誤表示を避ける。既存の
  `useDelayedFlag` を使う)。値は `useConnectivity()` で返す。
- Web版は完全版のFirestore SDK(`*.web.ts`)で同じ購読を作る。
- 再試行は `disableNetwork()` → `enableNetwork()` を順に呼んで再接続させる。
- 判定は Firestore の接続状態に依存するため、機内モードにしてから表示が変わるまで数秒遅れることがある
  (採用した方針の欠点。NetInfo を足さない代わりに受け入れる)。

### 4.2 帯と未同期件数

- 画面上部の `OfflineBanner`: オフライン時は「オフラインです。変更は端末に保存され、復帰後に自動で
  同期します」と再試行ボタン。未同期があれば件数も出す。オンラインで未送信が残る間は「同期中です」。
- 件数は、リスト詳細の項目スナップショットで `doc.metadata.hasPendingWrites` が true の項目を数える。
  リスト詳細だけが対象。一覧画面は帯のみで件数を出さない。
- 既存の「未同期の変更があります」の帯は `OfflineBanner` に置き換える(1秒の遅延は件数の帯にも使う)。

### 4.3 オンライン必須の操作(OFF-001)

- オフライン時は次を無効にし、「オフラインのため使えません。オンライン接続が必要です」を表示する:
  招待の発行・取消、メンバーの削除・オーナー移譲・退出、リストの作成・複製・アーカイブ・削除。
- 無効化は画面側の事前判定。サーバー側の検証・Rulesは変えない。

### 4.4 項目編集の競合(OFF-002)

- 編集画面は、開いた時点の項目(基準)を保持し、保存時に基準と入力を比べて**変えた項目だけ**を
  `updateListItem` へ渡す(純粋関数 `diffItemFields`)。
- 保存時に最新の項目と基準を比べ、他のメンバーが変えた項目(`remoteChanged`)を求める。
  - 自分が変えた項目と重ならない → 確認なしで保存する(Firestoreが項目単位で統合する)。
  - 重なる項目がある → 比較ダイアログを出す。「あなた」「相手」の値を重なった項目ごとに並べ、
    「相手の変更を使う / 自分の変更で上書き」を選ばせる(従来の2択を維持)。
- 完了状態も項目の1つとして同じ規則で扱う。

### 4.5 削除対編集(OFF-002)

- 削除を優先する。編集中に項目が削除された(他端末)と分かったら、編集画面に「この項目は削除されました」
  を出し、保存を止める。
- 入力内容は「新しい項目として追加」できる(同じリストに、入力内容で新規作成)。仕様書の「入力内容を
  コピーできる」を、ライブラリを足さずに満たすための**私の判断**。
- 自分がオフラインで編集し、復帰後に既に削除済みと分かる場合は、削除が残る(編集は論理削除済みの
  ドキュメントへ書かれるが `deletedAt` を変えないため、一覧には出ない)。

### 4.6 自動テスト(OFF-003)

- Emulator 上の通しスクリプト(既存の `e2e-share-ac01.mjs` と同じ方式)で、実際のFirestore SDKを使い、
  `disableNetwork()` / `enableNetwork()` で機内モードを再現する。
  1. オフラインで追加・編集・完了・削除 → 即時にローカルへ反映、`hasPendingWrites` が true。
  2. 復帰 → 自動同期され、別クライアントへ届く。
  3. 2クライアントで別の項目を同時に変更 → 両方残る。
  4. 同じ項目の別項目 → 両方残る。同じ項目 → 後着の値に収束(従来のLWW)。
  5. 削除と編集の競合 → 削除が優先され、編集後も一覧に出ない。
- CI(`ci.yml`)に追加する。結果は `docs/offline-005-ac03.md` に記録する。

## 5. 制約

- 開発ビルドの作り直しが要る変更(ネイティブ依存の追加)は入れない。
- 実機は使えない(ENV-002)。シミュレーター2台での確認は、時間があれば別途。
- Rules・Cloud Functions の変更は想定しない(クライアント側の変更と、Emulator上のテストのみ)。

## 6. 実装者に任せる点

- `OfflineBanner` の見た目・文言の細部、比較ダイアログのレイアウト(既存の design-system を使う)。
- `diffItemFields` / 競合判定の純粋関数の切り出し方とテスト。
- 無効化する操作ごとの文言(理由の一文)。
