## 1. 確認方法と未実施の範囲

実際のOpenAIクライアントは本EPICでは作っていない(外部準備: APIキー・モデル名の確定が前提)。生成の呼び出しは
`AiClient` インターフェースで、Emulator・CI・ローカル開発は偽のクライアント(`AI_CLIENT=fake`)を使う。
未設定のサーバーは「AI生成は準備中です」と失敗し、回数は戻る。

- 通しテスト: `AI_CLIENT=fake firebase emulators:exec --only auth,firestore,functions 'pnpm --filter mobile run e2e:ai'`
  (`apps/mobile/scripts/e2e-ai-ac05.mjs`、CIの `e2e:ai`。ホストにJavaが要る。Homebrewのopenjdkは
  `PATH=/opt/homebrew/opt/openjdk/bin:$PATH` を通す)。
- サーバー処理は、Emulatorの統合テストで回数の状態機械(予約・確定・返却・キャンセル・同時1件・失効・日本時間の月の境界)と
  保存(上限・再送)を確認している(`aiStore.integration.test.ts`)。画面はユニット・画面テストで確認した。
- 未実施: 実際のOpenAI APIでの生成と、50ケースの評価の実行、画面の目視(実機・シミュレーター・ブラウザ)、課金(EPIC-08)。

## 3. 評価セット(AI-005)

- `functions/ai-eval/cases.json`: 旅行15・登山15・買い物10・学校行事10の50ケース(人数・年齢帯・季節・特徴を変えている)。
- `functions/ai-eval/evaluate.ts`: 判定は、スキーマ適合・80件以内・重複なし・危険な提案なし・人数が数量に反映・季節が反映・
  乳児の年齢帯が反映。危険語(`DANGEROUS_TERMS`)と季節語(`SEASON_TERMS`)は、評価の結果を見て育てる最低限のリスト。
- 判定自体はフィクスチャでテストし(`evaluate.test.ts`)、偽のクライアントは50ケースすべてに合格する。
- 実行: `AI_CLIENT=fake pnpm run ai:eval`(偽のクライアントで仕組みを確認)。未設定で実行すると案内を出して終了する(終了コード2)。

### 実際のモデルで評価する手順(実クライアントができたあと)

1. OpenAIのAPIキーを、サーバー専用のSecretとして設定する(`firebase functions:secrets:set OPENAI_API_KEY`。ローカルは `functions/.secret.local`)。
2. 実クライアントを `AiClient` として実装し、`getAiClient` で選べるようにする(別チケット)。
3. モデル名を `config/ai`(`freeModel` / `premiumModel`)に設定する。既定値(`gpt-5.6-luna` / `gpt-5.6-terra`)は設計書の初期案で、実際に使える名前で上書きする。
4. `pnpm run ai:eval` を実行し、不合格のケースの内容を見て、プロンプトや判定語を直す。プロンプト・モデルを変えるたびに回帰として実行する。

## 4. 観測と注意

- **まだ無い文書の購読**: 結果画面は、サーバーが予約する前から `aiRequests/{uid}_{requestId}` を購読する。文書が無いときも
  読めるよう、Rulesはid(uid接頭辞)と文書のuidで本人を判定する(通しテストで見つかった)。
- **「次回も使う」**: 用途・人数・年齢帯・期間・季節・特徴だけを `users/{uid}/generationProfiles/default` に保存する(自由記述・メモは保存しない)。
- **モデル名**: 設定値で持ち、アプリの更新なしで変えられる。既定値は仮の値。
- **Premium失効後**: Freeの生涯1回は、Premium期間中の使用回数とは別に数える(Premiumの月次はキーが別)。
- **生成の呼び出し時間**: 1回30秒・再試行1回で、最大約1分。Callableのタイムアウトは90秒。
