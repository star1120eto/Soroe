# 完了判定と提出前検証

## 1. チケットの Definition of Done

全チケット共通。上から順に確認する。

```bash
pnpm run ci                              # build:shared → lint → typecheck → test → build:functions
pnpm --filter functions run test:rules   # Security Rules（Emulator、Java 21以上が必要）
```

CI が緑になったうえで：

- [ ] エラー、連打、戻る操作、通信断のうち該当ケースを確認した
- [ ] 主要操作にアクセシビリティラベルがあり、タップ領域が 44×44pt 以上
- [ ] 表示文言が日本語・英語リソースを経由している
- [ ] 個人情報や本文データをログ・分析へ送っていない（`git diff` で `console.log` を確認）
- [ ] 実機確認が必要なチケットは iPhone Development Build で確認した

画面チケットは追加で状態網羅：

- [ ] 通常 / 空 / 読込 / エラー / 無効 / オフライン のうち該当する状態を実装した

## 2. コミットとPR

コミットメッセージの先頭は必ずチケットID。`scripts/status.sh` がこれを読んで進捗を判定する。

```
LIST-003: リスト詳細の購読と項目の高速追加・チェックを実装
SHARE-002: createInvite/acceptInvite/取消をrequestId冪等で実装
EXT-004: OTP送信ドメインのDKIM/SPF認証完了を記録
```

複数チケットをまとめた場合は `AUTH-002/003/005:` のようにスラッシュで並べる（既存の前例あり）。

外部作業（コードを書かないもの）も `docs/` に完了記録を1〜数行書いてから同じ書式でコミットする。`docs/spike-001-offline-sync.md`、`docs/firebase-deploy.md` が前例。記録がないと後日「DNS認証は済んでいたか」を思い出せない。

## 5. 提出直前チェックリスト

REL-002b の直前に上から順に確認する。

- [ ] `pnpm run ci` と `pnpm --filter functions run test:rules` が緑
- [ ] production ビルドが実機で起動し、初回起動から招待受諾まで通る
- [ ] Firestore Rules と Functions が production プロジェクト（`soroe-1850a`）へデプロイ済み

- [ ] アカウント削除が Apple / Google / メールの3方式すべてで完了する
- [ ] `PrivacyInfo.xcprivacy` が含まれ、App Privacy 回答が実態と一致
- [ ] 輸出コンプライアンスの申告が済んでいる

- [ ] 審査メモにデモアカウント・デモ招待リンク・アカウント削除の場所が書いてある

## 6. リジェクトされたとき

Apple の指摘文にある Guideline 番号を上の表から引き、該当する Step へ戻る。指摘は1件でも、同じ Step の他項目も一緒に見直す（同種の見落としが並んでいることが多い）。

修正内容は `docs/` に記録してからコミットする。再提出時の審査メモに「前回の指摘への対応」として書く材料になる。
